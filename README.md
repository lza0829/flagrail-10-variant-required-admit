## 已落地：变体必填准入

多变体开关入轨时 `variant` 必填，契约与入轨同票同成败（单事务，违约整批回滚）。

- **物化契约表 `变体契约`**：每开关一行，含 `默认变体` 列与准入口径；`GET/POST /api/变体契约`。
- **缺字段准入门二选**：
  - `补齐`——可入轨，载荷写入默认 `variant`，核证落补齐标记；下发/回读只见补齐后载荷。
  - `拒收`——失败闭：无版本行、无核证行、无批次报告。
- **核证表 `变体核证`**：记录是否补齐、补齐后载荷快照、违约原因、valid；`GET /api/变体核证`。
- **下发读路径失败闭**：`GET /api/边缘载荷/{version_key}` 与出票前校验同闸，无契约/核证/空洞变体一律 400，空洞载荷不得静默出站。
- **观测点可区分**：拒收后版本不存在；补齐后版本存在且含默认 variant + 补齐标记（开关轨、变体契约页可见）。
- 贯验纳入契约三联互证：缺核证 / invalid / 空洞变体载荷 → 不通过。
- 核证脚本：`PYTHONPATH=backend python backend/tests/test_变体必填准入.py`（8 场景）。
